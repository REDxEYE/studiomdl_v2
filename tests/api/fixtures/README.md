# API test fixtures

SMD/VTA sources and QCs for the model builder API tests (`tests/api/harness.hpp`). Everything here is generated by
`make_fixtures.py` (pure standard library, deterministic: no randomness or timestamps, LF line endings, floats as
`%.6f`; running it twice gives byte-identical files) and the generated files are committed. Re-run the script only to
change a fixture:

    python3 tests/api/fixtures/make_fixtures.py

Every QC (except `anim_error_activity.qc`, which fails on purpose) compiles with `studiomdl_v2` (checked against the reference binary with the golden game directory, cwd =
this directory, `studiomdl_v2 -game <dir> <qc>`): exit code 0 and the warning counts below. Tests get the reference
output with `CompileQcReference(FixturePath("<name>.qc"))`; the keys are `models/api/<name>.mdl` etc.

## SMD / VTA conventions

- `src/*.smd` reference SMDs: `version 1`, contiguous node indices (parent index < child index), a single
  `skeleton` frame (`time 0`) with local position + RadianEuler per node, triangles with the material name line
  followed by three corner lines (`bone x y z nx ny nz u v` and, for skinned corners, `numlinks bone weight ...`).
  Corners without links are bound to the corner's bone with weight 1. Corners of one face share positions with the
  neighbouring faces (boxes are written with per-face normals, tubes/spheres with smooth normals).
- `src/anims/*.smd`: the same node list as the model they animate, `time 0..N-1` skeleton frames, no triangles.
- `src/*.vta`: `version 1` nodes + `time 0` base frame (every vertex) + `time 1..K` frames holding only the changed
  vertices. VTA vertex index = unique SMD position in first-seen order (normal of the first corner at that position),
  which is the mapping studiomdl's `Load_VTA` rebuilds (`MapVtaToGeometry` in `harness.hpp` replicates it).
- Material names are bare (`crate_wood`, no extension); every QC uses `$cdmaterials "models/api"`.
- All QCs write `$modelname "api/<name>.mdl"`; each compile produces `models/api/<name>.mdl`, `.vvd`, `.dx90.vtx`
  (and `.phy` for the two collision QCs).

## Things the compiler taught us while building these

- `$model "name" "file" {` needs the opening brace on the same line (the model-option parser reads tokens of the
  current line); a brace on its own line fails with `bad command {`.
- `$hgroup <group> <bone>` takes bone names (not hit group names); each hitbox group needs its bone to exist.
- `removemesh "<material>"` works when the replacement source of that LOD does not contain the mesh (`lod.qc`:
  `lod_low.smd` has no `lod_trim`). When the LOD's source still holds the removed mesh, the compile aborts with
  `too many bones/vert (191)` (or `too few bones/vert (0)` warnings + `Aborted vertex sort fixup`): `UnifyLODs.cpp`
  leaves the vertex index maps of a removed mesh uninitialised (`memset 0xDD`). This is behaviour of the existing
  compiler, so the fixture avoids it; the API's LOD part must reproduce whatever the QC path does for the same data.

## Core part fixtures (`core_*.qc`, tests/api/test_core.cpp and test_core_bones.cpp)

Hand-written (not made by `make_fixtures.py`), except that they use its sources. The builder model of each test is
compared byte for byte with the compile of the QC; the test sets `qc_path` of the model to the QC's path
(`QcPathEntry`), because a QC compile records it in the .mdl and a builder model has none by default.

- `core_prop_static`, `core_prop_multi`, `core_skinned`, `core_bodygroups`, `core_restpose`, `core_options`,
  `core_appendsource`, `core_override`, `core_globals`: bodies, skeleton, geometry and model-wide settings.
- `core_bones_define` (`$realignbones`, `$lockbonelengths`, `$root`, `$definebone`, `$forcerealign`),
  `core_bones_collapse`, `core_bones_collapse_aggressive`, `core_bones_aggressive` (`$unlockdefinebones`),
  `core_bones_flags` (`$controller`, `$screenalign`, `$worldalign`, `$bonemerge`, `$bonealwayssetup`,
  `$limitrotation`, `$bonesaveframe`, `$jointsurfaceprop`, `$jointcontents`): bone options, in the order the builder
  applies them. Sources: `src/biped.smd`, `src/core_bones_extra.smd` (bones root, mid, extra_a, extra_b, side; vertices
  on mid and extra_a).
- `-t <texture>` (texture replacement) is passed to the reference compile as an extra argument.
- `SMDL_TEST_DUMP=<dir>` keeps both sides of a mismatching comparison for diffing.

## DMX fixtures

`src/combo.dmx` / `src/combo_rules.dmx` (keyvalues2, written by `make_fixtures.py`, tables `COMBO_*`): a 12 vertex two-row strip, one bone `root`, one material `combo_mat`, 11 delta states, balance per column. `tests/api/test_combination.cpp` builds the same data through the API (the numbers are mirrored there: keep them in step). Differences between the DMX loader and the builder that the equivalence test accounts for: the DMX loader orders unified vertices by first use, the SMD-based builder by last use (the strip makes both the vertex order); the DMX loader normalizes normals (`(0,0,1)` becomes `(0,0,0.99999988)`, the builder stores what it is given); DMX materials are relative to `materials/` (`Geometry::setRelativeMaterials`); the DMX bone rotation `(0,0,0,1)` is euler `(0,-0,0)`; the vertex animation entries come in reverse order of the shape's vertex list.
