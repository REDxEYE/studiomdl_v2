# Golden-output test (`ctest -R golden`)

`run_golden.py` compiles every `fixtures/*.qc` with `studiomdl_v2` into a temporary game directory and compares the exit code
and the SHA-256 of every output file (`.mdl`, `.vvd`, `.dx90.vtx`, ...) with `fixtures/expected.json`.
The compiler output is deterministic, so any byte change shows up.

```
python3 tests/golden/run_golden.py --studiomdl /tmp/v2build/studiomdl_v2            # check
python3 tests/golden/run_golden.py --studiomdl ... --keep /tmp/golden_out            # keep outputs + logs for inspection
python3 tests/golden/run_golden.py --studiomdl ... --update                          # accept the current output
python3 tests/golden/run_golden.py --studiomdl ... -- -minlod 1                      # extra studiomdl arguments
```

Run `--update` only when an output change is intended, and say why in the commit. To inspect a change, compare two `--keep`
directories with the dump scripts in `testfiles/mdl_tools/`, or with `sfm_diff.py`.

## Fixtures

| QC | Covers |
|---|---|
| `character.qc` | DMX, two materials, `$texturegroup` skins, bodygroup with `blank`, `$lod` + `replacemodel`, flexes incl. a corrective (`Bulge_Pinch`), `$attachment`, bone animation sequence |
| `prop_static.qc` | `$staticprop`, unskinned |
| `smd_vta.qc` | SMD reference + old-style VTA flexes (`flexfile`, `flexcontroller`, `%flex = controller` rules) |
| `split_flexopt_off.qc` / `split_flexopt_on.qc` | vertex-count split (`$maxverts`), flex optimization off/on |
| `suzanne_binary_dmx.qc` | older binary DMX export, backslash in `$modelname` |
| `error_missing_source.qc` | error path: exit code 255, no output |

`$collisionmodel` is not covered: studiomdl_v2 has no physics support yet (`bad command $collisionmodel`).

The sources in `fixtures/src` (except `Suzanne.dmx` and `anims/ArmatureAction.dmx`, which predate the generator) are generated by
`fixtures/make_fixtures.py` with Blender + Blender Source Tools:

```
blender -b --factory-startup --python tests/golden/fixtures/make_fixtures.py -- tests/golden/fixtures/src
```

The generator is deterministic. Notes on Blender Source Tools (in Blender 5.2 beta, background mode):
- In keyvalues2 mode it writes `"name" string` with no value for unnamed elements, which the Valve keyvalues2 reader rejects,
  so the fixtures are binary DMX.
- An object with a single shape key gets an empty delta; every fixture mesh with flexes therefore has at least two shape keys.
- The exported delta of a shape key does not always match the key alone (the counts suggest neighbouring keys are mixed in).
  The fixtures only need deterministic, partial flexes, so this was not investigated further.

## Non-ASCII paths (`ctest -R golden_unicode`)

`unicode/Модели/` holds `персонаж.qc`, which reads `общее.qci` (`$include`), `исходники/тело.smd` + `тело.vta`,
`исходники/шляпа.dmx` and, through `$pushd "исходники"`, `анимации/движение.smd`. The SMD/VTA files are hand-written
(a quad on the `root`/`spine`/`head` rig); `шляпа.dmx` is a copy of `fixtures/src/Hat.dmx`. Names inside the files and the
output (`golden/unicode.mdl`) are ASCII. `golden_unicode` runs it by name from its directory, `golden_unicode_absolute`
with `--absolute-qc` (absolute QC path, run from another directory); both use the same `expected.json`.

On Linux paths are plain bytes, so these mostly guard against regressions. The real failure was on Windows (`main` got the
arguments in the ANSI code page, so Cyrillic became `?`). The outputs differ between Linux and Windows (e.g. the
lowercased `qc_path` key value), so check the Windows build under Wine by exit code and output files instead of the hashes:

```
EXE=$PWD/build-win/studiomdl_v2.exe                # from the repository root, after ./winbuild.sh
mkdir -p /tmp/g && cp <a gameinfo.txt> /tmp/g/    # e.g. the GAMEINFO text in run_golden.py
cd "tests/golden/unicode/Модели" && wine "$EXE" -game 'Z:\tmp\g' персонаж.qc
wine "$EXE" -game 'Z:\tmp\g' "Z:$PWD/персонаж.qc"  # absolute path (Z:/... works under Wine)
```

Each run must end with `Completed "персонаж.qc"` and write `models/golden/unicode.{mdl,vvd,dx90.vtx}` under `/tmp/g`.

## Extra fixture directories

Models that can't be committed (e.g. user models) can be checked the same way: put the QCs and an `expected.json` (created with
`--update`) in a directory and pass `--fixtures DIR`, or list such directories in `STUDIOMDL_GOLDEN_FIXTURES`
(separated by `os.pathsep`). ctest picks the variable up too.
